# BEMESTATE

관심 단지의 **특정 평형** 호가 목록을 매일 오전 9시 30분(한국 시간)에 기록해 두는 페이지.
직방과 네이버 부동산의 매물을 한 목록에 모으고, 국토교통부 실거래가를 곁에 둔다.
모양과 구조는 BEMTRIP(`bemrung2/sandbox`)을 따른다 — 빌드 없는 바닐라 JS, Vercel 함수, Supabase.

## 어디에 뭐가 있나

```
index.html · app.js   껍데기와 주소 (#/ 목록 · #/w/<id>/<날짜> 단지 하나)
ui/                   BEMTRIP에서 가져온 부품 — 창 · 아이콘 · 알림 · 주소 · 테마
estate/               화면(screens) · 숫자와 바깥 링크(format) · 호가 흐름 그림(chart)
style/core.css        BEMTRIP의 토큰과 부품 그대로
style/estate.css      이 앱의 화면
api/watch.js          관심 목록과 기록 읽기 · 등록 · 네이버 연결 · 해제
api/search.js         단지 검색 · 평형 목록 · 네이버 단지 찾기
api/collect.js        정해진 시각의 수집 (Vercel Cron이 부른다)
api/probe.js          이 서버가 직방 · 실거래가에 닿는지 보는 주소
extension/            네이버 매물을 날마다 가져오는 크롬 확장 (내 컴퓨터의 크롬에 깐다)
api/_data.js          저장소 — Supabase, 또는 로컬 파일
collect/run.js        수집 한 바퀴: 플랫폼별 매물을 한 기록으로 합친다
collect/zigbang.js    직방 · collect/naver.js 네이버 부동산 · collect/molit.js 실거래가
collect/kb.js         KB부동산에서 네이버 단지 코드 찾기 · collect/hogangnono.js 호갱노노 단지 번호
db/schema.sql         표 두 개: estate_watches · estate_snapshots
```

## 기록되는 것

- 등록할 때 **같은 평형 묶기**를 켜면 전용 면적이 1㎡ 안에서 같은 평형들(59A · 59B …)이 한 관심으로 묶인다
  (`room_types`). 이 기능을 쓰려면 `db/schema.sql`을 한 번 다시 실행해 칸을 더해야 한다.
- 관심 하나 = **단지 × 평형 × 거래(매매 · 전세)**. 단지와 평형은 직방의 번호로 잡고,
  네이버 부동산은 단지 번호와 면적(공급 · 전용)으로 같은 평형을 가려낸다.
- 기록 하나 = 그날(`2026-11-11`)의 호가 목록 전체와 최저 · 중간 · 최고 · 건수.
  매물마다 어느 플랫폼 것인지(`src`)가 붙고, 화면에서는 뱃지로 보인다. 누르면 그 플랫폼의 매물 화면으로 간다.
- 같은 날 다시 수집하면 **답한 플랫폼의 매물만** 바뀐다. 답하지 않은 플랫폼은 그날 먼저 받아둔 것이 남는다.
- 날짜 줄 맨 앞의 **현재**를 누르면 그 자리에서 플랫폼에 물어 지금 올라와 있는 호가를 보여준다 (기록하지는 않는다).
- 목록은 카드로도, 한 줄씩(간단히 보기)으로도 본다. 카드나 줄을 왼쪽으로 밀면 삭제 단추가 나온다.
  삭제는 몇 초 동안 되돌릴 수 있고, 그 시간이 지나야 기록과 함께 실제로 지워진다.
- 화면은 직전 기록과 견주어 **신규 · 가격 변동 · 빠진 매물**을 표시하고, 호가 흐름(최저–최고 범위,
  최저 · 중간 선, 실거래 점)을 한 그림에 그린다.
- 가격은 전부 만원.

## 무엇이 확인됐고 무엇이 아닌가

| 부분 | 상태 |
| --- | --- |
| 직방 매물 | **확인됨.** 실제 응답으로 검색 · 평형 · 수집을 돌려봤다. |
| 직방 매물 링크 | 확인 안 됨. `www.zigbang.com/home/apt/items/<번호>` 형식으로 만들지만 만든 환경에서는 직방 웹이 열리지 않았다. |
| 네이버 부동산 매물 | 서버 수집은 안 됨. 크롬 확장(`extension/`)이 날마다 가져온다 — 붙여 받은 실제 화면 한 장을 로컬에서 대신 내보내 시험함. 진짜 네이버에서는 미확인. |
| 실거래가 | **확인됨.** 배포된 곳의 `/api/probe`에서 실제 거래가 단지 · 평형으로 가려지는 것을 봤다. |
| 호갱노노 단추 | 단지 이름으로 찾은 화면(`hogangnono.com/search?q=…`)으로 간다. 호갱노노의 단지 번호는 알 수 없다. |

## 네이버 부동산

**서버는 네이버를 부르지 않는다.** 네이버는 공개 API가 없고 클라우드 서버의 연결을 받지 않는다(Vercel 서울
리전에서 5ms 만에 거절). 차단이나 검사 방지를 속여 넘기는 장치는 넣지 않았다.

대신 **내 컴퓨터의 크롬에 깐 확장(`extension/`)이 날마다 가져온다.** 정해 둔 시각(기본 09:40)에 관심 단지마다
네이버 부동산의 매물 탭(`fin.land.naver.com/complexes/<번호>?tab=article`)을 작은 창으로 열어, 화면에 뜬 목록을
끝까지 내려 읽고 BEMESTATE에 보낸 뒤 창을 닫는다. 사람이 그 화면을 열어 보는 일을 대신 하는 것이다.

### 까는 법 (한 번)

1. 이 저장소를 내려받는다 (GitHub의 Code → Download ZIP, 압축 풀기).
2. 크롬 주소창에 `chrome://extensions` → 오른쪽 위 **개발자 모드** 켜기 → **압축해제된 확장 프로그램을 로드합니다** →
   내려받은 것 안의 `extension` 폴더를 고른다.
3. 확장 아이콘을 눌러 **BEMESTATE 주소**(예: `https://….vercel.app`)를 넣고 **저장**. **지금 가져오기**로 바로 시험한다.

### 알아 둘 것

- 그 시각에 **크롬이 켜져 있어야** 한다. 꺼져 있었으면 다음에 크롬을 켤 때 그날 치를 한 번 따라잡는다.
- 같은 네이버 단지를 보는 관심 평형이 한 번에 채워진다. 매물은 거래 방식과 전용 면적으로 평형을 가린다 (월세는 버린다).
- 그날의 네이버 매물이 통째로 바뀐다. 아침 9시 30분 서버 수집은 직방만 새로 받고 네이버 것은 그대로 둔다.
- 팝업에 단지마다 결과가 남는다. 덜 읽혔거나 실패한 날은 아이콘에 `!`가 붙는다.
- 여러 중개사가 묶어 올린 매물은 화면에 매물 번호가 없을 수 있어, 눌렀을 때 단지의 매물 탭으로 간다.
- 네이버가 화면 구조를 바꾸면 `extension/background.js`의 고르는 말(`ArticleCard` · `__price` …)을, 글귀를 바꾸면
  `collect/naver.js`의 읽는 법을 고친다. 네이버가 그 창에 목록을 띄워 주지 않으면 그날은 건너뛴다.

단지 번호는 KB부동산이 알려주는 네이버 단지 코드로 자동으로 잇는다(`collect/kb.js`).

## 실거래가

국토교통부 실거래가 공개 API를 쓴다. [공공데이터포털](https://www.data.go.kr)에서 아래 둘을 활용신청하고
받은 **일반 인증키(Decoding)** 를 `MOLIT_SERVICE_KEY`에 넣는다. 없으면 실거래가만 비고 나머지는 그대로 돈다.

- 국토교통부_아파트 매매 실거래가 상세 자료
- 국토교통부_아파트 전월세 실거래가 자료

단지(법정동 + 지번)와 평형(전용 면적)으로 가려 **5년치**를 쌓는다. 처음에는 30달씩 거슬러 받고
(단지 화면을 열 때와 아침 수집 때), 다 받은 뒤로는 최근 석 달만 다시 받는다. 화면은 최근 5년를 먼저
보여주고, 최근 3년 · 1년 · 3개월로 좁힐 수 있다 — 단추마다 그 기간의 건수가 적혀 있다.

**실거래가가 안 보일 때**는 `https://<도메인>/api/probe`를 연다. `deals`에 관심 단지마다 이렇게 찍힌다:

- `error` — 키가 없거나, 등록되지 않았거나(활용신청 승인 전 · 잘못 붙여넣음), API에 닿지 못했다.
- `rows_in_district` — 그 구의 최근 석 달치 거래 수(여기서는 석 달만 본다). 0이면 답은 왔는데 비어 있다.
- `rows_of_complex` — 그중 이 단지(법정동 + 지번, 안 되면 이름)의 것. 0이면 단지를 못 가려냈다.
- `rows_of_this_type` — 그중 이 평형(전용 면적 ±0.5㎡)의 것. `areas_of_complex`에 그 단지에서 거래된 면적들이 나온다.
- `sample_row` — 받은 거래 한 건을 읽은 그대로.

인증키는 Decoding · Encoding 어느 쪽을 넣어도 된다.

## 내 컴퓨터에서

```bash
node dev.js
```

`http://localhost:3000` — 계정 없이 파일(`.estate-dev.json`)에 저장한다. `SUPABASE_URL`을 주면 진짜 저장소에 붙는다.

## 배포 (Vercel + Supabase)

1. Supabase SQL Editor에 `db/schema.sql`을 붙여넣고 실행. **전에 실행했더라도 다시 실행한다** — 새 칸이 더해지고,
   예전의 00시 기록이 지워진다.
2. Vercel → 프로젝트 → Settings → Environment Variables

   | 이름 | 값 |
   | --- | --- |
   | `SUPABASE_URL` | Supabase → Project Settings → API의 Project URL (`https://xxxx.supabase.co`) |
   | `SUPABASE_SERVICE_ROLE_KEY` | 같은 화면의 `service_role` 키 (`anon` 키가 아니다) |
   | `CRON_SECRET` | 아무 긴 임의 문자열 (`openssl rand -base64 32`). 없으면 아침 수집이 돌지 않는다 |
   | `MOLIT_SERVICE_KEY` | (선택) 공공데이터포털 인증키. 실거래가를 켠다 |
   | `KAKAO_REST_KEY` | 카카오 개발자 콘솔의 REST API 키. **없으면 편집이 잠기지 않는다** |
   | `KAKAO_OWNER_ID` | 편집할 수 있는 카카오 계정의 회원번호 (처음 로그인하면 화면이 알려준다) |
   | `KAKAO_CLIENT_SECRET` | (선택) 콘솔에서 Client Secret을 켰을 때만 |

   넣은 뒤 다시 배포해야 적용된다.
3. 보는 것은 주소를 아는 누구나 한다. **등록 · 수정 · 삭제는 카카오로 로그인한 주인 한 사람만** 한다 (아래).
   크롬 확장이 네이버 매물을 넣는 일(`importNaver`)은 로그인 없이 받는다.
4. 수집 시각은 `vercel.json`의 `crons` — UTC 00:30 = 한국 오전 9시 30분.
   Hobby 요금제는 정각에서 최대 한 시간까지 늦게 돌 수 있다.

## 카카오 로그인 (편집 잠금)

1. [카카오 개발자 콘솔](https://developers.kakao.com)에서 앱을 만들고 **카카오 로그인**을 켠다.
2. Redirect URI에 `https://<내 주소>/api/auth`를 등록한다.
3. 앱 키의 **REST API 키**를 Vercel 환경변수 `KAKAO_REST_KEY`에 넣고 다시 배포한다. 이때부터 편집이 잠긴다.
4. 첫 화면 오른쪽 위의 로그인 단추로 카카오 로그인을 하면, 화면이 그 계정의 **회원번호**를 알려준다.
   그 번호를 `KAKAO_OWNER_ID`에 넣고 다시 배포한다. 이제 그 계정만 편집할 수 있다.

로그인하면 서명한 쿠키(30일)를 받는다. 서명 열쇠는 `SESSION_SECRET`, 없으면 `CRON_SECRET`이다.
